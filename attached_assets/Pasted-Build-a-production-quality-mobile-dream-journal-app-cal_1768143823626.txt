Build a production-quality mobile dream journal app called “Driim” using React Native (Expo) + TypeScript. The app must be offline-first, fast, and structured cleanly.

Tech stack (required)

Expo (latest) + TypeScript

expo-router for navigation

Tamagui for UI (or if Tamagui setup is too heavy in Replit, use React Native Paper — but try Tamagui first)

Local database: expo-sqlite (SQLite). Use a small data access layer/repository pattern.

Local secure storage: expo-secure-store (for auth token + encryption key)

Notifications: expo-notifications

File export + share: expo-file-system + expo-sharing

Optional biometric lock: expo-local-authentication

State: simple (React context + hooks) or Zustand (either ok)

Core product goals

The user writes dreams quickly on their phone by the bed.

App works fully offline.

Powerful organization + search + insights.

Optional sync to a backend API (REST) when online.

Features to implement
1) Authentication (optional but implemented)

Implement a simple auth flow that can be toggled:

Screens: Sign In, Sign Up, Continue Offline

If user continues offline: app stores dreams locally only

If user signs in: store token in SecureStore and enable sync

Assume backend endpoints (do not require backend to exist; mock with a local service file):

POST /auth/signup {email, password}

POST /auth/login {email, password}

Returns { token, userId }

Keep base URL configurable in src/config.ts:

API_BASE_URL = "https://api.driim.app" (placeholder)

Entry UI

“Quick Add” bottom button always available

Editor supports:

autosave drafts

templates: “Short”, “Detailed”, “Lucid Practice”

Attachments:

audio recording (voice note)

images (optional)
Store attachments locally (file paths) and link in DB.

3) Offline-first architecture + sync queue

All writes go to SQLite first.

Build a SyncService that:

queues operations: create/update/delete

runs on app start + when user pulls to refresh + when network becomes available

resolves conflicts by “last write wins” but mark as conflict if both changed since last sync

Assume backend endpoints:

GET /dreams?since=timestamp

POST /dreams (create)

PUT /dreams/:id

DELETE /dreams/:id

If backend unreachable, keep pending.

recurring only

Sort:

Implement with SQLite queries + simple tokenization.
